# Synthetic store-sales dataset

Generated by `scripts/generate_synthetic_data.py` (seed 660, deterministic with the pinned versions in `requirements.txt`).
Covers the 42 days 2026-09-16 through 2026-10-27 (six Wednesday-to-Tuesday ad weeks)
for 40 stores and 160 SKUs. `manifest.json` lists exact row counts and every injected
defect by ID.

| File | Grain | Rows | Key |
|---|---|---|---|
| `store_reference.csv` | one row per store (intended) | 41 | `store_code` |
| `sku_master.csv` | one row per SKU | 160 | `sku` |
| `planogram.csv` | one row per store-SKU shelf slot (intended) | 4,037 | `planogram_id` |
| `daily_sku_sales.csv` | one row per slot per business date while on the shelf | 165,644 | `planogram_id`, `business_date` |

Relationships: `planogram.store_code → store_reference.store_code`,
`planogram.sku → sku_master.sku`,
`daily_sku_sales.planogram_id → planogram.planogram_id`.

The published category mart (`category_daily_units.csv`) is not stored here. It is
built from these four files by `scripts/build_category_mart.py`; see the main
[README](../../README.md#data-dictionary).

## How the data is shaped

- **Assortment.** 80 items in 18 categories across 7 departments, each stocked under
  a national brand and the co-op's private label, Meridian Select. Supermarkets carry
  about 75% of the assortment, neighborhood stores 60%, express stores 40%.
- **Demand.** Category velocity × SKU appeal × store traffic, with Saturday and Sunday
  peaks, drawn as Poisson counts. About 3% of slots are new items cut in during the
  window and about 2% are discontinued during it (85 `REMOVED` slots).
- **Promotions.** Each ad week, 12% of SKUs go on ad (114 events in all), 70% chain-wide
  and 30% in one region. A promotion discounts 10–35% and lifts volume roughly 1.6–2.6×.
  About 9% of sales rows are promotion days.
- **Baskets, shrink and waste.** `basket_count` is between 1 and `units_sold` on any day
  with sales. Shrink occurs on every item at about 1% of volume; perishable waste only
  on perishable SKUs, at 1–8% of volume depending on category.

## Injected defects

These are deliberate. They are the failure classes the quality gates must catch.

| Defect | Table | Count |
|---|---|---|
| Duplicate `planogram_id` (1 exact double-load, 2 with conflicting store/shelf location) | planogram | 3 IDs, 3 extra rows |
| `store_code` not in store_reference (`ST041` ×2, `ST099`, `ST000`, `ST7`) | planogram | 5 |
| Null `sku` (slot exported before the item was keyed in the item file) | planogram | 4 |
| Duplicate `store_code` key: `ST017` appears twice (district re-org row never retired) | store_reference | 1 extra row |
| Decimal-shift spike: one day's `units_sold` posted ×100 (28 → 2,800) | daily_sku_sales | 1 row |

The `ST017` duplicate reproduces last quarter's incident: joining sales to
`store_reference` on `store_code` doubles every ST017 slot (133 planogram rows), which
inflates chain-wide units sold on 2026-10-27 by 987 units (about 4.1%). No row is lost
and nothing errors, so the overstatement is silent.

Everything else is clean: `daily_sku_sales` has no orphan slots and no duplicate
`(planogram_id, business_date)` pairs, every non-null `sku` resolves, and the largest
units-to-median multiple on an established slot is 6.7×, under the 10× business rule.

To regenerate:

```
python scripts/generate_synthetic_data.py              # this defective dataset
python scripts/generate_synthetic_data.py --clean --out build/data
```
